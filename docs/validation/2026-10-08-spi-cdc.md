# 2026-10-08 SPI→USB 验收

硬件：HPM5301EVKLite akaLinkPro，F103ZE（SWD 读得 512 KiB Flash），SPI1 PA4/5/6/7 接探针原 SPI2，引脚见 [功能说明](../spi-cdc.md)。目标 CPU 实读 72 MHz。探针运行 `build_dfu_evklite` 新固件；CDC COM5，USB 高速连接。发送端、探针都实际烧录并验证。

## 字节率和完整性

MB/s 为主机收到的字节数 / 实测秒数 / 1,000,000，不是探针搬运计数，也不是串口波特率。

| 用例 | 时钟 | 测量时长 | 主机实收 | 数据检查 |
| --- | --- | --- | --- | --- |
| Python CDC，SPIC 序号帧 | 4.5 MHz | 10 s | 0.562625 MB/s | 缺序号、乱序、字节错误均 0 |
| Python CDC，SPIC 序号帧 | 9 MHz | 10 s | 1.125358 MB/s | 同上 |
| Python CDC，SPIC 序号帧 | 18 MHz | 10 s | 2.250331 MB/s | 同上 |
| Python CDC，SPIC 序号帧 | 18 MHz | 20 s | 2.250342 MB/s，45,007,796 B | 703,247 个完整帧，缺序号/乱序/字节错误 0，发送端补缓冲迟到 0 |
| Python CDC，hello world | 18 MHz | 5 s | 2.251212 MB/s | 每字节匹配循环 hello world 字符串 |
| **真实 SPI→USB 页面，Web Serial** | **18 MHz** | **10.0043 s** | **2.250098 MB/s** | 全流 371,476 完整帧，缺序号/乱序/字节错误 0 |
| 四种 Mode × MSB/LSB | 9 MHz | 各 2 s | 约 1.125 MB/s | 八组合全部通过 |

上述所有正常用例探针 `dropped`、FIFO 溢出与 DMA 错误均 0。20 s 用例与模式矩阵读取目标时钟及补缓冲计数；最初三档 10 s 用例仅字节率/内容/探针计数有效，原始目标指标正则未解析十六进制，显示 0，不能据此证明目标状态。脚本已修订并在后续用例验证。

Mode 覆盖最初暴露了测试发送端的 CPOL=1 启停错误：CS 先拉低再使能 SPI，会把建立空闲 SCK 的边沿算入数据。修正为先使能 SPI 建立空闲时钟，再选择从机；停止先释放 CS。最终八种组合重新全量通过。保留的 modes 原始数据是修正后结果。

## 背压与恢复

故意关闭 CDC 接收口，18 MHz 继续发送约 0.5 s：探针 CDC 队列填满 32,768 B，DMA 保留最新 8192 B，丢弃计数 1,146,765 B；FIFO/DMA 错误仍为 0。此时请求启用 SPI 主机得到 `SB_E_BUSY=8`，从机继续运行。重新打开 CDC 后搬运恢复，无设备复位。停止后再 START，收得 4,981,331 B，77,833 完整帧，无缺序号、乱序、字节错误或探针丢弃。此用例验证慢主机下有界丢弃和可恢复性，不宣称丢弃阶段无损。

## 网页与回归

真实网页 18 MHz 测试中高流量显示门控生效，20 ms 心跳最大间隔 35 ms，页面未卡死；停止转发后接收串口保持打开。独立假探针真页面测试覆盖启动/停止/断开按钮、模式、位顺序、入口顺序、无重复 DOM ID、接收/独立清空/暂停/恢复、高速显示恢复；注入 4,915,200 B，记录内容逐字节一致，最大心跳间隔约 33 ms。

- `make test-host` 全部通过。生产 SPI 服务另测失败初始化归还资源、STOP/USB reset 取消待启动、DMA 圈尾、CDC 在途存储保护、复制预算、溢出、故障及重启、未支持板型。
- Web `make test-stability` 通过；新增 SPI 协议/会话测试覆盖延迟连接、START 中断开、STOP 失败保留占用、RTT/SPI 主机交接、共用串口不重开、SWD 共存。
- 所有 13 页在 1600/1280 宽度布局共 58 项通过，SPI→USB 截图人工检查通过。
