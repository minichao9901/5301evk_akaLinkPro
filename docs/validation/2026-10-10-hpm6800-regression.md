# HPM6800EVK 回归性能修复（2026-10-09～10）

本次目标板为 HPM6800EVK / HPM6880；本仓构建并烧录的是 EVKLite 探针固件。相同网页与相同 HSS 目标 ELF，对比当前基础 `2df2d39` 和历史源码 `ecebd8a` 的独立重编译版本。

## 固件改动

- 主循环 `main` 放入 ILM `.fast`，减少持续采样时主循环的 XIP 指令读取。
- SWO 服务的 pending / token 成为可内联读取的同一份权威状态。空闲时跳过服务调用，活跃租约和待处理命令仍会进入服务，保持超时与时钟恢复逻辑。
- 仅移动已有状态和派发位置，没有修改 RISC-V SBA 算法、采样协议或采样周期，没有调整 CPU 频率。ILM 占用约 32,240 B / 128 KiB。
- 默认 UART 根时钟保留 240 MHz。有效租约释放 / 超时后仍恢复这个默认值。

## 同机旧、新版本对比

单位为 kSa/s，8 秒稳态窗口、绘图 / 自适应开启、CDC 暂停。旧版是源码重编译结果，并非历史测试原始二进制。

| 1 变量 3.25 µs，批读 | 302.476 | 299.260 | 302.732 |

2 µs 饱和档下降从约 2.31% 缩小到 0.78%；不批读路径仍低约 1.89%，没有完全恢复。去掉新增派发、改变主循环位置等独立试验能改善结果，支持主循环派发及指令布局是主要因素。没有采集 cache-miss 计数器，XIP 工作集 / 缓存冲突解释属于推断，剩余开销尚未逐周期定位。

2 µs 请求 500 kSa/s 已高于实际能力，因此修改后跳过请求周期约 39.62%，旧版约 39.15%。8 变量 40 µs（25 kSa/s）开启自适应并施加 25 ms 宿主停顿，USB 丢包 / 错值 0。关闭自适应后同样压力会丢包，旧、新版均有，不能混为默认模式的误码。

## 实机验收

- 综合场景 10 项通过、0 失败：烧录及读回验证、RTT Viewer、RTT 转发及存盘、JScope、flood / scope 交替烧录。
- Viewer 65.1 KiB/s，RTT 转发 1.384745 MiB/s；RTT 历史吞吐 1.376～1.377 MiB/s，未下降。
- JScope 综合场景单 / 三变量饱和约 302.8 / 51.8 kSa/s；单变量 50 kSa/s、三变量 33.333 kSa/s 无跳拍 / USB 丢包 / 样本缺口。
- 调试压力 57 项通过，包括 19 个单步地址与反汇编基准核对；非法指令现场正确解码 mcause=2、mepc=0x80005554、mtval=0xffffffff。
- SWO 1 Mbps 的心跳 / 释放、23 Mbps 的 PLL1 实际调频 / 5 秒租约超时恢复通过；CPU 时钟、36 个时钟节点、PLL1 配置前后核对一致。

原始 DMI 异常实际由网页仓库回归脚本将成功文字当错误、在 RTT 读指针写回期间并发初始化 TAP 引起，脚本已修复。不是探针 Flash porting 算法失效。

另用序号 + CRC 临时靶子定位浏览器接收的偶发缺口。网页 RTT 接收缓冲从 4 KiB 调整到 64 KiB，并保留每 8 ms 让出事件循环。60 秒、87,379,968 B、341,327 个完整帧，在每秒 25 ms 主线程停顿下 CRC / 载荷坏值 / 缺号 / 重复 / 乱序均为 0。该修复在网页仓库，不能称为探针每比特 BER 的全面证明。完整实验、失败记录和数据口径见 `E:/web-serial-rtt-tools/docs/validation/2026-10-09-hpm6800evk-regression.md` 与同目录结构化 JSON。
